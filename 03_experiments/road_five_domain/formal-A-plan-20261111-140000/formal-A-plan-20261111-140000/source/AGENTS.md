# 科研复现工作规范

## 研究原则

- 以论文、官方 README 和源代码为依据，忠实复现；区分作者原始实现、必要的兼容性修复和实验方法改动。
- 优先保留原始模型结构、损失函数、训练策略、数据划分和评估方法。对论文与代码的不一致进行调查，并记录最终采用的依据。
- 通过针对性实验验证问题原因，使结论与实际证据对应；每个阶段以可验证的成果作为完成标准。

## 代码和环境

- 每篇论文使用独立的 Conda 环境；依源代码、官方要求和实际兼容性测试确定依赖版本。
- 定位问题根因，采用直接、简洁的修复，尽量保持原始代码结构，并通过 Git diff 审查修改。
- 保持 WSL2 的 NVIDIA GPU 支持，使用 Windows 提供的 GPU 驱动。
- 数据集、checkpoint、日志和其他大型生成文件保存在本地，不新增到 Git；保留上游已跟踪的示例和日志。
- 完整训练前先通过小规模验证确认代码正确。

## 实验规范

- 区分快速调试和正式复现实验。每次正式实验明确目标、配置、代码版本、数据划分、初始化权重和随机种子。
- 每个实验使用可区分的独立输出目录，集中保存实际运行命令、配置、训练日志、评估结果和 checkpoint。
- 记录 batch size、学习率、迭代次数等可能影响结论的参数变化及原因。
- 启动耗时的正式训练前，先向用户报告实验方案并取得确认。

## 工作方式

- 复杂任务先分析相关文件再确定方案；简单任务直接执行并报告结果。针对当前问题按需读取项目文件。
- 任务结束时简要说明修改、验证结果和遗留问题。阶段完成、关键决策或重要阻碍出现时更新 `REPRO.md`，保持单一当前状态。
- 使用 Git、实验日志和训练输出追溯细节；新对话通过本文件、`REPRO.md` 和相关代码恢复上下文。
- 删除数据、覆盖 checkpoint、修改系统级环境、执行大规模下载、Git 提交或推送等影响较大的操作前，先取得用户确认。
