用于长期维护文献、复现、实验、机器人部署和论文写作记录，并支持 Codex 跨会话恢复工作。当前进度以 [PROJECT_STATE.md](00_management/PROJECT_STATE.md) 为准，待办以 [TASKS.md](00_management/TASKS.md) 为准。

原始任务书保留为 [20260928144022150248_盛曦-毕业设计(论文)任务书2.doc](<20260928144022150248_盛曦-毕业设计(论文)任务书2.doc>)，不另建或重命名为 `任务书.doc`。已有综述保留在 [综述/](综述/)，由索引引用，无需迁移。

## 记录与命名

- 文献 ID 稳定且不复用；综述与原始论文共用 `LIT-001` 起的编号。阅读报告通过 ID 与索引关联。
- 任务、决策和实验分别使用 `T-001`、`D-001`、`EXP-001` 起的编号。日期采用 `YYYY-MM-DD`，时区为 Asia/Shanghai。
- 实验正式记录与结果摘要应保存为文件，记录代码版本、环境、数据版本与划分、命令、配置、种子及指标；临时输出不能代替正式记录。
- 研究状态只在状态文件中维护摘要；任务清单管理执行状态，日志保留历史，其他文件用链接关联，避免维护多套当前进度。

## Git 使用

建议纳入版本控制：管理 Markdown、索引与报告、源代码、配置、环境说明、会议纪要和可复核的小型结果摘要，以及本地原始任务书和综述 PDF。`.gitignore` 不屏蔽 PDF、DOC、DOCX 或 Markdown。

大型权重、原始数据集、缓存、临时输出与本地虚拟环境由 `.gitignore` 排除。被排除文件仍保留在磁盘；正式实验配置、指标摘要与日志不要放在被忽略的临时目录。需要复现的大文件，应在相应成果目录记录来源、版本、校验值和获取方式。

本地版本管理与对外公开是不同操作。初始化不自动暂存、提交、创建远程仓库或推送；后续 Git 操作遵循用户授权。
